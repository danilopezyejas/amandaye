# Correcciones de seguridad — socios_amandaye

Estado del trabajo: 14/09/2026. Se modificó el código y la configuración de ejecución para corregir los 13 hallazgos de [la auditoría inicial](INFORME.md), usando las categorías de [OWASP Top 10:2025](https://top10.owasp.org/2025/). El diagnóstico original conserva los escenarios de explotación y las ubicaciones anteriores; los enlaces siguientes señalan la implementación actual.

Las correcciones se entregan en este conjunto de cambios. No se han publicado ni aplicado a la base operativa. Los archivos sensibles y generados se retiraron del seguimiento de Git; sus copias locales se conservan. La limpieza del historial compartido sigue siendo una operación aparte.

## Cambios por hallazgo

| Hallazgo y OWASP | Remediación implementada y ubicación actual |
|---|---|
| **H01 — A01 Broken Access Control** | [ClubPermissions](../../amandaye_backend/apps/usuarios/permissions.py) deniega por defecto y exige usuario activo y permiso por operación. Los mapas explícitos cubren socios, cuentas, cargos, pagos, aplicaciones y reportes. Las [consultas HTML](../../amandaye_backend/apps/usuarios/urls.py) requieren permiso de personas. La única inscripción pública admite datos limitados, crea pendientes y devuelve una confirmación mínima 202, igual para cédulas ya registradas. |
| **H02 — A06 Insecure Design** | [API de cobranzas](../../amandaye_backend/apps/cobranzas/views.py) elimina PUT/PATCH/DELETE genéricos de movimientos; altas y acciones pasan por servicios autorizados con operador tomado del servidor. [Admin](../../amandaye_backend/apps/cobranzas/admin.py) conserva inmutables importes, vínculos y estados, impide borrados y evita que un formulario obsoleto revierta pagos. [Migración 0008](../../amandaye_backend/apps/cobranzas/migrations/0008_proteger_movimientos_y_auditoria.py) incorpora auditoría de cargos/reversiones y PROTECT para aplicaciones de pagos. |
| **H03 — A01 Broken Access Control** | [SociosAdmin](../../amandaye_backend/apps/usuarios/admin.py) protege estados, fechas, identidad primaria y tipo de cuota frente a POST forjados y formularios obsoletos. Altas administrativas quedan pendientes. [Servicios de socios](../../amandaye_backend/apps/usuarios/services/socios.py) verifican permisos de Directiva, registran actor y usan transacciones. Se cerró además la concesión de BECA/EXONERADO por Secretaría: Directiva dispone de una acción específica con motivo y auditoría para las cuotas futuras. |
| **H04 — A04 Cryptographic Failures** | [Settings](../../amandaye_backend/amandaye_backend/settings.py) exige claves Django/JWT independientes y sin valor predeterminado. El [generador de secretos](../../scripts/bootstrap_secrets.py) crea valores aleatorios en un directorio privado excluido de Git y Docker, sin mostrarlos ni sobrescribir credenciales existentes. Se prepararon juegos distintos para producción y desarrollo. Es necesario activar estas claves en el despliegue existente para invalidar las firmas antiguas. |
| **H05 — A02 Security Misconfiguration** | [Compose de producción](../../docker-compose.yml) usa una cuenta `amandaye_app`, contraseñas mediante archivos de secretos y redes internas para MySQL/Redis, sin sus puertos publicados. El backend rechaza el usuario root y contraseñas vacías; exige red privada declarada o TLS con verificación de identidad. MySQL inicializa un volumen nuevo. Los usuarios y contraseñas de una base anterior deben migrarse/provisionarse expresamente. |
| **H06 — A02 / A04** | [Dockerfile](../../Dockerfile) usa Python 3.12 y Gunicorn sin root. El [gateway](../../docker/gateway/Caddyfile) sirve el frontend compilado mediante HTTPS y sustituye los encabezados de proxy; solo publica 80/443. Producción fuerza DEBUG desactivado, hosts explícitos, cookies Secure y redirección HTTPS. [Desarrollo](../../docker-compose.dev.yml) es independiente y solo publica en loopback. |
| **H07 — A03 Software Supply Chain Failures** | [Package y lock](../../amandaye_frontend/package.json) actualizan Vite a 7.3.6, Axios/PostCSS y sus transitivas. Vite y preview escuchan en loopback; producción sirve recursos compilados. El [transporte autenticado](../../amandaye_frontend/src/api/client.ts) impide enviar credenciales a otro origen y evita carreras de refresh/logout. |
| **H08 — A03 Software Supply Chain Failures** | [Dependencias Python](../../amandaye_backend/requirements.txt) fijadas con hashes, Django 5.2.17 LTS y mysqlclient 2.2.8 sobre Python 3.12. Se retiró la adaptación con PyMySQL y se actualizó DRF, JWT y demás dependencias. La imagen instala con `--require-hashes`. La auditoría de paquetes no sustituye el mantenimiento periódico de imágenes y del sistema operativo. |
| **H09 — A06 Insecure Design** | [Movimientos](../../amandaye_backend/apps/cobranzas/services/movimientos.py), [pagos](../../amandaye_backend/apps/cobranzas/services/pagos.py) y [cargos](../../amandaye_backend/apps/cobranzas/services/cargos.py) bloquean cuenta → pago → cargo → aplicaciones, vuelven a leer saldos actuales y validan importes finitos, positivos y de dos decimales. La reversión solo ocurre una vez. [Generación de cuotas](../../amandaye_backend/apps/cobranzas/services/cuotas.py) se serializa con cambios/cierre de socio y cuenta. |
| **H10 — A07 Authentication Failures** | [Autenticación](../../amandaye_backend/amandaye_backend/security/authentication.py) integra Axes en JWT y login HTML/admin: cinco fallos, bloqueo por cuenta o IP y enfriamiento de 15 minutos. Límites de solicitud/refresh usan caché compartida Redis en producción. El cliente no puede elegir la IP mediante encabezados arbitrarios. Refresh tokens rotan y entran en blacklist. |
| **H11 — A01 Broken Access Control** | [.gitignore](../../.gitignore) y [.dockerignore](../../.dockerignore) excluyen secretos, SQLite, el dump personal y archivos generados. `.env`, SQLite, SQL personal, bytecode y node_modules se retiraron del índice sin borrar las copias de disco. El dump ya no se monta en MySQL y los secretos no se copian a las imágenes. **Pendiente externo:** purgar versiones históricas, clones o imágenes ya compartidas y retirar credenciales antiguas activas, si existen. |
| **H12 — A01 Broken Access Control** | [URLs](../../amandaye_backend/amandaye_backend/urls.py) usa destinos locales explícitos y devuelve un 404 real. Se eliminó el middleware que redirigía usando Referer. |
| **H13 — A10 Mishandling of Exceptional Conditions** | [Errores de API](../../amandaye_backend/apps/usuarios/api_errors.py) y [handler global](../../amandaye_backend/amandaye_backend/security/exceptions.py) conservan errores de validación controlados y dan mensajes genéricos con identificador para fallos inesperados. Los logs no incluyen texto SQL ni trazas con datos. Baja, cierre, auditoría y recálculo se confirman juntos o se revierten; un error al consultar deuda deja de interpretarse como habilitación. |

## Verificación

- Backend local: **104 pruebas descubiertas, 100 aprobadas y 4 omitidas** exclusivamente por ausencia de bloqueos de filas en SQLite. [Salida guardada](backend_tests_after.txt). Incluye permisos, acceso anónimo, escalada por formularios, importes, autoría, rollback, login/CSRF, rotación JWT, redirecciones y configuración de producción.
- MySQL 8.4: **104 pruebas aprobadas, sin omisiones**, con las migraciones aplicadas sobre una base sintética desechable. Incluye las cuatro carreras financieras: un pago/dos cargos, dos pagos/un cargo, aplicación/anulación y doble reversión. [Salida guardada](backend_mysql_tests_after.txt). Entorno reproducible en [docker-compose.test.yml](../../docker-compose.test.yml).
- Frontend: **7 pruebas aprobadas** y compilación Vite correcta. Auditorías npm/pip actualizadas el 14/09/2026, sin vulnerabilidades conocidas en los árboles comprobados: [Python](backend_dependencies_after.json) y [npm](frontend_dependencies_after.json).
- Django: `makemigrations --check --dry-run` sin cambios pendientes de generar; comprobación ordinaria sin incidencias. Migración 0008 incluida.
- Producción: imagen del backend y gateway construidas; instalación de dependencias con hashes verificada. Caddy validó la configuración sin root y sin red externa; su respuesta HTTP devolvió 308 hacia `https://club.example.test/`, sin el puerto interno. `collectstatic` terminó correctamente con el almacenamiento de producción. `check --deploy` solo recomienda HSTS para subdominios y precarga (W005/W021), deliberadamente sin activar hasta verificar el dominio completo.
- Secretos: creación idempotente, independencia, archivos derivados de Redis coherentes, rutas restringidas, permisos de acceso y ausencia de valores en salida comprobados. Se verificó además su montaje real en el backend sin root, con sistema de archivos de solo lectura, sin red y con estáticos en tmpfs. En Windows se asignaron a la cuenta Danilo que ejecuta Docker y a SYSTEM. Las bases reales no se utilizaron.
- Limpieza: se retiraron el contenedor de comprobación del gateway y el MySQL temporal de pruebas, junto con su red. No se borraron volúmenes ni datos del entorno operativo.

Los scripts `verify_api.py`, `verify_config.py` y `verify_report.py` de esta carpeta documentan la reproducción del código anterior. Las regresiones del código corregido están en los módulos `test_*security.py` y `amandaye_backend/security/`; los scripts anteriores no son la suite de aceptación del parche.

## Aplicación al entorno operativo

Seguir [DEPLOYMENT.md](../../docs/DEPLOYMENT.md): restauración ensayada en una base nueva o provisión explícita de usuario, migraciones de aplicación/Axes/blacklist, `setup_roles`, activación de claves nuevas y verificación del dominio HTTPS. No se ensayó una restauración de datos reales ni se emitió un certificado público para el dominio del club.

La configuración de este repositorio protege despliegues que se construyan y arranquen con ella. No cambia por sí sola un servidor existente, sus credenciales ni el historial remoto. El informe distingue esas tareas operativas de las correcciones de código comprobadas; no constituye una garantía de ausencia total de vulnerabilidades.
